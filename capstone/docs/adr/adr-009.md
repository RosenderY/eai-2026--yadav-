# ADR-009 — Publish causal hops to a wire tap

## Context

An HTTP call crosses the process boundary after an AMQP delivery. A single order ID does not identify which attempt caused a later call.

## Decision

Allocate a hop ID before the provider call, send it in X-Causation-Id and publish duration and status independently. Every retry starts from the original message header and carries its own attempt number.

## Alternatives considered

Collecting logs from every service on demand makes debugging depend on every service being online. Blocking checkout on trace confirms adds an operational dependency.

## Consequences

The trace queue buffers while observer is down. Losing an unpublished hop can leave a gap even when the order completed.
