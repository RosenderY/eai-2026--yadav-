# ADR-001 — Confirm publication and acknowledge after writing

## Context

A 202 receipt should survive a broker restart. A stopped consumer may take minutes to resume. HTTP request identifiers also have to survive this separation.

## Decision

Declare the queue durable on both ends. Confirm each persistent publish. Carry the ID as the AMQP correlationId property. Append and flush the JSONL line before acknowledging.

## Alternatives considered

A socket write can finish before RabbitMQ records the message. Fire-and-forget demonstrates that weaker promise. Acknowledging on receipt also leaves a loss window before the append.

## Consequences

The caller waits for a broker round trip. A crash after the append and before the ack can repeat a line; consumers requiring one effect need a persistent dedupe key.
