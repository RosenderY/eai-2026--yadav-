# ADR-006 — Run checkout on Temporal

## Context

A PA6 process restart interrupts the local coordinator between provider calls. A durable execution history can preserve which steps have returned.

## Decision

Keep HTTP in six activities. A 4xx is final. Other failures get up to three attempts at 2.5 seconds each. Register undo actions after each successful reservation or authorization and execute them newest first.

## Alternatives considered

Persisting a step pointer in the API keeps dependencies smaller but requires hand-written recovery and retry timers.

## Consequences

Recovery now depends on Temporal availability. An activity can still cause an effect before its completion reaches history, so provider dedupe remains important.

## What the engine took over

- Persisting activity results for replay after a worker restart.
- Scheduling the retry delays and enforcing per-attempt timeouts.
- Correlating API requests and durable executions through workflow IDs.
